# ⚡ Світло БЦ

Android-застосунок із графіком відключень світла ДТЕК для Білої Церкви (стиль One UI).
Дані автоматично збирає безкоштовний GitHub, ваш комп'ютер для цього не потрібен.

```
GitHub Actions (кожні 15 хв) ─► відкриває сайт ДТЕК браузером ─► файл schedule.json (гілка data)
                                                                          │
Телефон (застосунок) ◄───────── читає schedule.json кожні 5 хв ──────────┘
```

Раз на тиждень окремий процес «Карта адрес» обходить усі вулиці міста на сайті ДТЕК і складає
публічну таблицю «вулиця + будинок → черга» (гілка map). У застосунку ви вводите свою адресу, і черга
визначається сама. Ваша адреса зберігається лише на телефоні, у репозиторії її немає.

## Можливості (версія 0.3)

- Кілька адрес на головній сторінці, у кожної свій стан і графік.
- Налаштування: мова (українська, English), стиль (One UI або iOS зі скляним ефектом), сповіщення.
- Сповіщення за 15, 30 або 60 хвилин до відключення і до увімкнення світла. Вони плануються на
  телефоні на 3 доби вперед після кожного оновлення графіка, тому приходять і без інтернету.
  Якщо кілька днів не відкривати застосунок, а графік зміниться, сповіщення можуть бути застарілими.

## Встановлення на телефон (один раз, ~15 хв)

1. **GitHub.** Створіть безкоштовний акаунт на github.com → «New repository» → назва
   `svitlo-bc`, тип **Public** (публічний, інакше телефон не зможе читати дані й Actions
   обмежені) → Create.
2. **Завантаження файлів.** На сторінці репозиторію: «uploading an existing file».
   Розпакуйте архів, **видаліть теку `node_modules`, якщо вона є**, і перетягніть у вікно
   *вміст* теки `svitlo-bc` (теки `.github`, `app`, `assets`, `scripts`, `server`, `test` і файли).
   Натисніть «Commit changes».
3. **Автозапуск.** Відкрийте вкладку **Actions**. Там мають з'явитися три процеси:
   «Оновлення графіка» (~3 хв), «Збірка APK» (~10 хв) і «Карта адрес» (до години, перший раз
   запустіть вручну: Run workflow). Якщо їх немає, відкрийте кожен
   зі списку ліворуч і натисніть «Run workflow». Зелена галочка означає успіх.
4. **APK.** Репозиторій → праворуч «Releases» → «Світло БЦ (остання збірка)» → завантажте
   `svitlo.apk` на телефон → відкрийте → дозвольте встановлення з цього джерела.
5. **Перший запуск.** Відкрийте застосунок і додайте адресу (вулиця й будинок із підказками). Якщо
   адреси не знайшлося, є запасний варіант: вибрати чергу вручну.

Оновлення застосунку: змініть файли в репозиторії, і APK збереться заново. Перед встановленням нової
версії видаліть стару (підпис debug-збірки щоразу новий); адресу доведеться ввести знову.

## Якщо щось не працює

- **«Оновлення графіка» червоне.** Відкрийте запуск → розгорніть червоний крок і скиньте текст помилки.
  Найімовірніша причина: ДТЕК блокує IP-адреси GitHub. Тоді дані можна оновлювати з вашого
  комп'ютера: `npm run fetch`, і вміст `out/schedule.json` вручну класти в гілку `data`.
- **У застосунку «Дані на сервері не оновлювались N год».** Збір даних зупинився (див. вище).
  GitHub також вимикає заплановані запуски після 60 днів без активності репозиторію: просто
  натисніть «Run workflow» у вкладці Actions.
- **«Збірка APK» червона.** Скиньте текст помилки з червоного кроку.

## Перегляд на комп'ютері

Потрібен Node.js 20+.

```
npm run demo      # вигадані дані → http://localhost:3000
npm install
npx playwright install chromium
npm start         # реальні дані ДТЕК → http://localhost:3000
npm test
```

## Структура

- `app/www/` — застосунок (HTML/CSS/JS)
- `server/dtek.js`, `server/snapshot.js` — доступ до ДТЕК і формат знімка графіків
- `scripts/` — збір даних, підготовка Android-збірки
- `.github/workflows/` — автоматичний збір даних і збірка APK
- `assets/android-res/` — іконки застосунку

## Що не перевірено

Збір даних для всіх черг одним запитом перевірено лише на вигаданих даних. Реальну відповідь ДТЕК
для вашої адреси застосунок розібрав правильно, але чи містить вона всі черги разом, покаже перший
запуск (у разі потреби виправлення мінімальне, у `server/snapshot.js`). Збірку APK у GitHub Actions
я не запускав: вона може потребувати невеликих правок після першого запуску.
